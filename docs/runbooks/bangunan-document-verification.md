# Bangunan document verification

Implemented under ADR-310 on 2026-10-28, on top of the existing iNDECS registration increment.

## Department checklist configuration

An authorised senior Bangunan officer or system administrator opens **Katalog dokumen** from the Bangunan case list. Select PB, PBK, PBS, PMT or TEL, enter the department's source reference and actual confirmed document requirements, then publish. At least one required document is necessary. The application records the confirming actor and a new catalogue version. No department requirement list or operational application is seeded by this feature.

Starting document verification snapshots the selected family's confirmed catalogue. Later catalogue edits apply to new checklists, preserving existing case requirements and names. If a case was already in document verification before this increment, its authorised reviewer explicitly initialises its checklist using the displayed record version. Starting or completing verification without a confirmed, non-empty checklist is refused.

## Upload and verification

Open a registered case, start document verification, and select **Buka dokumen dan pengesahan**. Upload each required document. PDFs and JPEG/PNG images are checked by actual content MIME, extension and the snapshotted size limit (the catalogue editor currently sets 20 MB). A real scanner must report clean before a private revision is saved. Filenames do not determine storage paths. Each revision retains SHA-256, uploader, time, scan state and its predecessor.

Reviewers accept or reject the current revision. Rejections require a reason; required documents cannot be waived. Optional supplied documents need acceptance or an explicit reason for being inapplicable. Replacements keep prior files and decisions but reset the checklist item for fresh verification. Record-version checks reject stale forms. Download routes enforce record access and case ownership and verify file integrity, including for older revisions.

From the case actions, reviewers can return the submission with a reason. Uploaders replace rejected files and submit again; review occurs after resubmission. Completing verification requires accepted current revisions for every required item and review of supplied optional files. The shared guarded workflow then moves the case to fee assessment. No fee amount, payment, technical approval or permit is generated by this increment.

## Deployment

With the correct environment and the platform baseline in place:

```sh
php artisan migrate --path=database/migrations/2026_10_28_000000_create_core_document_verification.php --force
php artisan db:seed --class=BangunanDocumentWorkflowSeeder --force
```

The dedicated seeder adds granular upload/verify/configure permissions and guarded document transitions to the unreleased version-1 Bangunan templates. It does not create or promote user accounts or populate business checklists. Existing core templates and roles must already exist. Do not run the full DatabaseSeeder against the consolidated development database for this feature.

Linux defaults use `clamscan` from PATH and its system signature configuration. Optional environment variables are `INDECS_DOCUMENT_SCANNER_BINARY`, `INDECS_DOCUMENT_SCANNER_DATABASE`, and `INDECS_DOCUMENT_SCANNER_CERTIFICATES`. Configure a current supported ClamAV installation and signature updates before accepting operational files. There is no scanner bypass: detections, nonzero scanner exits, unavailable executables and timeouts refuse uploads.

The local Windows workstation has the official portable ClamAV 1.5.4 package in ignored `.tools/clamav/`, with its official detached signature verified using the Talos key downloaded from the official site. FreshClam downloaded and verified the virus definitions. Local executable/database/certificate paths are in the untracked `.env`; committed defaults remain suitable for Linux. Run the local updater when maintaining this workstation (redirect its progress output to a local log):

```powershell
& '.tools/clamav/runtime/clamav-1.5.4.win.x64/freshclam.exe' --config-file='.tools/clamav/freshclam.conf' *> '.tools/clamav/update.log'
```

Arrange signature maintenance through the deployment's normal operating procedures. No recurring agent automation or production service was created. See the [official scanner documentation](https://docs.clamav.net/manual/Usage/Scanning.html) and [official downloads/signing-key page](https://www.clamav.net/downloads).

## Verification and recovery

Tests use the guarded disposable `indecs_test` database, fake private storage and an explicitly injected scanner test double. Adapter tests separately check clean, detection/error exits and unavailable scanning. Optional `INDECS_CAPTURE_DOCUMENT_VIEWS=1` captures actual Blade responses from test cases under ignored `.tools/bangunan-document-ui/` for visual checks; this is not an application mode or authentication bypass.

The new migration is additive. Rollback refuses to remove structures when checklist or scanned-document evidence exists. Without such evidence, rollback also removes the added guarded actions before dropping the guard column, preventing an older application binary from inheriting an unguarded completion action. Once documents exist, use a reviewed forward fix or a restore/reconciliation plan. Preserve private blobs, document metadata, catalogue attribution, audit and stage history together.
